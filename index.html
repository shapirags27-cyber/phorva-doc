02

The Problem

Having permission to execute does not guarantee the execution matches the original intent.

Declared intentSwap 300 USDC
Authorized limit500 USDC
Attempted execution3,000 USDC

Wallet

Can check whether the transaction is signed.

Policy system

Can check whether the transaction exceeds a limit.

Missing piece

Did the execution actually match the agent’s intended and authorized action?

03

How Phorva Works

Intent→ Policy→ Risk→ Auth→ Validate→ Execute→ Verify→ Proof

Phorva evaluates the relationship between intent, authorization, execution, and resulting state. The goal is not just “can this execute?” — it is “did what executed match what was authorized?”

04

Core Primitive: Proof-Carrying Agent Actions

A verified action carries evidence of what the agent intended, what was authorized, what was executed, how it was evaluated, the final state, and a canonical commitment.

Intent

What the agent intended

Authorization

What was authorized

Execution

What was actually executed

Evaluation

How the execution was evaluated

Final State

Resulting system / on-chain state

Commitment

Canonical commitment to the verified execution

10

What Phorva Is Not

Not an agent wallet

Does not hold assets or replace wallet infrastructure.

Not a prover marketplace

Defines verification semantics; external provers supply the machinery.

Not an agent platform

Developers build and operate the agents.

Not an execution environment

Does not replace blockchains, wallets, rails, or protocols.

Not a card issuer

Virtual Card is a future execution rail, not a Phorva product.

Not the decision-maker

Does not decide what the agent should do — only verifies consistency.
